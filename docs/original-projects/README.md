# Merge preservation inventory

`spring-api-concurrency-bottlenecks` is the runnable project. All four original comparisons and all four incoming comparisons are active in the root application. Both API families retain their URLs, request shapes, and response bodies.

## Original files and documentation

- [Original concurrency README](spring-api-concurrency-bottlenecks/README.md), its linked measurement data, and the original destination files adapted during integration are preserved unchanged.
- [Original saturation README and complete project](api-saturation-bottlenecks/README.md): every one of its **38 tracked files** is preserved byte-for-byte, including hidden files, Maven wrappers, configuration, seed data, sources, scripts, its measurement record, and diagnostic evidence.
- [SHA-256 inventory](manifest.json) records every source file, its original executable flag, archived location, active location, original source commit, and destination baseline commit/file hashes.

The archive is historical source material outside the root Maven source/resource directories. Use the [root README](../../README.md) and [adapted transfer-assessment guide](../api-saturation-bottlenecks/README.md) to run the merged application. Original validation claims and measurements describe the separate projects before the merge. Git metadata, ignored build output, and temporary profiling/load output are not source files and are not copied.

## Integration decisions

- One executable entry point: `ConcurrencyBottlenecksApplication`. The incoming `ApiSaturationApplication` becomes imported Spring configuration.
- Reuse the existing `virtualIoExecutor` / `virtualMvcExecutor`; retain the incoming 40-worker lock executor. Explicit bean names avoid collisions between the two packages without changing endpoint paths or class/package names.
- Register both JPA entity/repository packages. Existing numeric-ID accounts and history transfers retain their tables. Incoming string-ID accounts and assessment transfers use `saturation_account` and `saturation_transfer`, with unique JPA entity names.
- Keep the destination Maven artifact, H2 database name, batching settings, and original initializer. Consolidate incoming SQL initialization and Actuator thread-dump exposure into `application.yml`; `data.sql` seeds the six assessment accounts after schema creation.
- Both load scripts retain their original names and interfaces. Incoming evidence lives in `docs/api-saturation-bottlenecks/`; original concurrency evidence remains in `docs/measurements.json`.
- Every original case remains independently callable. No build, lint, test, startup, or load command was run during integration; original benchmark results have not been replaced or presented as merged-run results.
